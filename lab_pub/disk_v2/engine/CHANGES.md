# Disk Lab v2 のエンジン:由来と変更の記録

`engine/disk3d.js` は Disk Lab v2 自身のエンジンです(2026-10-16 から)。`lab/disk/disk3d.js` の写しとして始まり、
v2 の都合で手を入れてきました。上流と自動で揃えることはもうしません。上流の変更は `ver2/tools/disk-lab-v2/sync-engine.sh`
で差分として眺め、採るものだけを手で取り込み、この記録に足します。

今の写しの SHA-256 と、`app.js` の `ENGINE_SRC` の `?v=`(先頭 10 文字)は `SOURCE.txt` にあります。

## 採らなかったもの

| 候補 | 出どころ | 理由 |
|---|---|---|
| 位相時計の「wide phase」用の第 2 のプログラム群(TIME_MAX 1e6 を超えたら切り替える) | b | v2 の時計の上限は common path が精度を保つ範囲(約 2.1e6 s)の中にある。世代を 2^30 で折り返せば足り、プログラムを倍にするコンパイル時間と検証の手間に見合わない |
| 物質ごとの色(material palette、material-colours.mjs) | c | v2 のモデルの見え方は「色 = 温度」で、凡例もそれに合わせている。物質で塗ると温度の色と意味がぶつかる |
| ストリーマー(gpu-streamers)、惑星の配置(placement、planet-geometry)、光蒸発の EM(photoevaporation) | c | 新しい物理を見せるには、範囲の取り決め、文言、検証が要る。今回の範囲を超える。将来の候補 |
| CPU の描画経路(cpu-bridge、worker)と 2×2 の標本化 | c | v2 は GPU が足りない端末を静止画へ送る(quality.js)。動く絵は蓄積(accT)で滑らかさを得ており、2×2 は不要 |
| gpu-driver のフェンスによる待ち合わせ | c | v2 のフレーム制限(data-flight)が同じ役目を果たしている |

内側のガス円盤の切れ(指摘 1)と磁気圏のメッシュ(指摘 2)は、a、b、c のいずれでも直っていなかった(コードと絵で確認)。

## 上流の変更を見るとき

    sh ver2/tools/disk-lab-v2/sync-engine.sh            # 起点からの上流の差分(lab/disk と origin/main)を表示する

採るときは、手で取り込み、`SOURCE.txt` を書き直し、`ENGINE_SRC` の `?v=` を上げ、エンジンの検査(`engine-check.js`)と
check.js を回し、絵が変わったなら静止画を作り直して、この表に一行足す。
