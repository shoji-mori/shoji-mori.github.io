# 個人研究サイト全面リニューアル 設計書

日付: 2026-07-03
対象リポジトリ: shoji-mori.github.io(GitHub Pages, `main` ブランチ公開)

## 1. 目的とゴール

森 昇志(清華大学 Shuimu Fellow、理論天体物理)の個人サイトを全面リニューアルする。

- **最重要ゴール**: 採用担当者・審査員(日本の公募、海外ポジション、フェローシップ/グラント審査)への訴求力を最大化する
- 見た目・内容構成・情報量・技術基盤の全軸を刷新する
- 既存コンテンツ(研究紹介6テーマ、論文・発表データ、公開資料)は資産として活用してよい

### 成功基準

- 第一印象で研究者としての個性と格が伝わり、かつ審査員が目的の情報(論文・CV)に10秒以内に到達できる
- 業績データが常に最新(ADS週次同期)で、手作業の二重管理がない
- Lighthouse(Performance / Accessibility / Best Practices / SEO)全項目100点を目標とする
- 印刷(PDF化)しても美しく読める
- 公開作業は従来通り `git push` のみで完結する

## 2. デザインコンセプト:「特集記事」

一流科学誌(Quanta Magazine 等)があなたを特集したかのようなエディトリアルデザイン。派手な演出ではなく、組版・余白・図版の質で信頼感を作る。

### デザインシステム

- **紙面**: 生成りの紙色(#faf9f6 系)+ 濃いインク(#1a1a1a 系)。アクセントは2色のみ — 焦がしオレンジ(円盤内縁の色)と深宇宙紺
- **タイポグラフィ**: 見出しはセリフ体(欧文 Newsreader 系 / 和文 Noto Serif JP)、本文・キャプション・UIはサンセリフ(欧文 Inter 系 / 和文 Noto Sans JP)。言語トグルに応じて適切なフォントスタックへ切替。フォントはセルフホストし、`font-display: swap` と preload で最適化
- **Hero(トップのみ)**: 深宇宙紺のダークな導入部。「Where do planets come from?」の問いで始まり、背景にシミュレーション画像を静的に敷く。動画自動再生・大きなアニメーションは使わない。スクロールで白い誌面に移行
- **誌面の道具立て**: 大きな章番号(01–06)、図版には必ずキャプション(出典論文の引用付き)、欄外注(短い補足)、細い罫線
- **モーション**: 控えめなフェード/罫線アニメーション程度。`prefers-reduced-motion` を尊重
- **印刷CSS**: 全ページ印刷最適化。特に /cv と /publications は印刷での提出を想定した専用スタイル

## 3. サイト構成

### ページマップ

| ページ | 内容 |
|---|---|
| `/` | 問いの Hero → 数字サマリ帯 → 研究ハイライト3件(図版+平易な説明1〜2文+論文リンク)→ 最新 News 4件 → Selected Publications 5本 → フッター |
| `/research` | 研究紹介。現行の6テーマを「章」(01–06)として再構成。各章に図版・欄外注。本文は現行テキストをベースに磨く |
| `/publications` | 全論文のデータ駆動リスト。絞り込み(年・査読/その他・筆頭著者)。平易な要約の開閉、BibTeX コピー、DOI/arXiv/ADS リンク |
| `/talks` | 発表リスト(データ駆動。国際/国内・口頭/ポスターの別)+ 公開資料(スライド・ポスター・学位論文)を統合 |
| `/cv` | Web版CV(学歴・職歴・受賞・グラント・査読歴等)+ CV PDF ダウンロード。印刷最適化 |
| `/news` | 活動記録の全一覧(年別) |

- ヘッダー: サイト内ナビ + EN/JA トグル。フッター: 連絡先(メール)、ORCID / Google Scholar / ADS / researchmap / GitHub / ResearchGate / Scopus / Web of Science リンク一式
- 現行の問い合わせフォーム(Formspark、エンドポイント `https://submit-form.com/p3OcmXTQj`、ハニーポット付き)はフッター/コンタクト部に同じ仕組みで移植

### 多言語方式

- **現行のトグル方式を維持**する(ユーザー決定)。両言語をページ内に持ち、EN/JA ボタン+ `localStorage` で切替。言語別のURL(/ja/ ルート)は作らない
- `<html lang>` と各要素の `lang` 属性を正しく付与する

### URL・資産の互換性

- 旧アンカーURL(`/#publications` `/#research` 等)は新ページへクライアントサイドでリダイレクト(トップに小さなスクリプトを置く)
- `files/`(ポスター・スライド・学位論文)、CV PDF、`google382eb4ad681ea1fc.html`、`robots.txt` は同一URLで温存
- `sitemap.xml` はビルド時に自動生成へ置き換え

## 4. データ層(プロフェッショナル化)

**原則: 手で二重管理しない。書誌情報の正本は NASA ADS、サイト固有情報だけをローカルに持つ。**

### 論文データ

- **ADS 同期**: ADS API をORCID(0000-0002-7002-939X)で検索し、書誌メタデータ(タイトル・著者・誌名・巻号頁・DOI・arXiv ID・bibcode・被引用数・査読フラグ)を取得して `src/data/publications.generated.json` に書き出す
- **ローカルオーバーレイ**: ADS が持たない情報は `src/data/publications.overrides.yaml` に bibcode キーで保持 — `selected` フラグ、日英の平易な要約(現行データから移行)、著者名の日本語表記、ハイライト図版の指定。同期処理はこのファイルに**絶対に書き込まない**(手書き部分が上書きされない保証)
- **マージ**: ビルド時に generated + overrides を bibcode で結合して表示用データを構成
- **同期の実行**: `npm run sync` (ローカル)+ **GitHub Actions の週次 cron が自動実行し、変更があれば自動コミット→自動デプロイ**(ユーザー決定)。ADS API トークンは GitHub Secrets に保存
- **移行**: 既存 `publications_data.js` から一度だけ変換スクリプトで移行。DOI/arXiv ID で ADS レコードと突合し、要約・selected 等を overrides に振り分ける

### 発表・News・CV データ(外部DBなし、手入力)

- 発表: `src/data/presentations.yaml`(現行 `presentations_data.js` から移行。フィールド構造は維持)
- News: Astro content collection。`src/content/news/YYYY-MM-DD-slug.md` を1件1ファイルで追加するだけでトップと /news に反映
- CV: `src/data/cv.yaml`(経歴・受賞・グラント・査読歴等を構造化。現行 index.html の CV セクションから移行)

### スキーマ検証

- 全データに Zod スキーマ(Astro content collections / 独自ローダー)。不正データはビルド失敗となり、壊れた状態で公開されない

### 数字サマリ(自動計算)

- 査読論文数・筆頭著者論文数・総被引用数・h-index をビルド時に同期データから計算。手動更新は不要

### データの出口

- 各論文の BibTeX コピーボタン(ADS 由来の bibcode から生成)+ 全業績 `.bib` ダウンロード
- 論文ごとの JSON-LD(ScholarlyArticle)、Person の JSON-LD を自動生成
- 将来拡張(スコープ外): 同一データからの公募用業績リストPDF生成

### 障害時の挙動

- ADS API が落ちている場合、同期はエラー終了し**前回の generated データがそのまま残る**(サイトは壊れない)。週次 Action の失敗は GitHub の通知で気づける

## 5. 技術構成

- **Astro 5** による静的サイト生成。出力は純粋な静的HTML/CSS+最小限のJS
- クライアントJS は最小限: 言語トグル、論文フィルタ、BibTeX コピー、旧アンカーのリダイレクト程度
- **デプロイ**: GitHub Actions でビルド → GitHub Pages(Actions 方式に切替。初回のみリポジトリ設定変更が必要)。以後の公開は `git push` のみ
- **SEO**: ページ別 title/description、OGP、canonical、JSON-LD、自動 sitemap。現行のメタデータ資産を引き継いで強化
- リポジトリ構成: サイト本体をリポジトリルートの Astro プロジェクトに再構成。`admin/` は**今回のスコープ外**(触らない)。旧 `index.html` / `style.css` / `script.js` / `*_data.js` は移行完了後に削除

## 6. 必要な素材(ユーザー提供)

- 研究ハイライト用のシミュレーション静止画 3〜5枚(うち1枚は Hero 背景用)。**仮画像で実装を先行**し、後から差し替え可能な設計にする
- ADS API トークン(無料。ADS アカウント設定画面から取得し、GitHub Secrets に登録)

## 7. エラー処理・テスト

- ビルド時: スキーマ検証、内部リンク切れチェック、生成HTML の基本検証
- 同期スクリプト: ADS 応答の形式検証、overrides との突合で不一致(ADS にない bibcode 等)を警告
- 手動確認: ローカルプレビュー(`npm run dev`)での目視、日英トグル・印刷プレビュー・モバイル表示の確認
- Lighthouse 計測を実装完了条件に含める(全項目100点目標)

## 8. スコープ外

- `admin/` ディレクトリ(Next.js 管理アプリ雛形)の改修・削除
- 言語別URL(/ja/ ルート)方式への変更
- ブログ・解説記事などの新規執筆コンテンツ
- 公募用業績リストPDFの自動生成(データ構造はそれに耐える形にするのみ)

## 9. 決定の記録

| 論点 | 決定 | 備考 |
|---|---|---|
| デザイン方向 | B+C → コンセプト③「特集記事」 | ダーク宇宙Hero+白いエディトリアル誌面 |
| 演出レイヤー(円盤への旅/生きたシミュレーション) | 不採用 | 組版の質で勝負する正統派を選択 |
| ページ構成 | マルチページ(6ページ) | 1ページ構成から変更 |
| 多言語 | 現行トグル方式を維持 | ページは分けない(ユーザー明示指定) |
| 技術 | Astro 5 | 最新選択肢の比較の上で決定 |
| データ | ADS 週次自動同期 + ローカルオーバーレイ | 自動コミット方式 |
